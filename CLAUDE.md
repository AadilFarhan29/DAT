# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A static marketing site for **DAT International**, a UAE trading and distribution company. Fourteen pages — `index.html` (the main scrolling page), `leadership.html` (founder profiles), and **twelve brand detail pages**, one per tile in the Brands grid — all sharing one stylesheet and one script. There is no framework, build step, package manager, or backend.

## Commands

There is no build/lint/test tooling in this repo (no `package.json`, no bundler, no CI config).

- **Preview the site**: open any of the HTML files directly in a browser. A static file server (e.g. `python -m http.server`) also works but is not required.
- **No install step**: fonts are loaded from Google Fonts CDN via `<link>` tags in `<head>`; all other assets are local files in `assets/`.
- There is nothing to lint, compile, or test — validate changes by opening the page in a browser and checking the affected section/interaction.

## Architecture

At the repo root:

- `index.html` — the main page (~670 lines of markup).
- `leadership.html` — the founder-profiles page.
- **Twelve brand detail pages** — `flyzo.html`, `leo-toy.html`, `toy-box.html`, `petal-muse.html`, `vol.html`, `dfun.html`, `the-play-zo.html`, `hippo.html`, `dtoy.html`, `funqb.html`, `teq.html`, `little-trendz.html` (see *Brand detail pages* below).
- `styles.css` — **all** CSS for every page (~1590 lines).
- `script.js` — **all** JS for every page (~230 lines).

Plus `assets/` (images, logos, favicons, hero banner, the Markets SVG map) and the SEO files `sitemap.xml` / `robots.txt`. **Every new page must be added to `sitemap.xml`.**

Note there is **no `assets/brand-logos/` subfolder** — every brand logo sits directly in `assets/`, and the same file serves both the Brands grid tile and its detail page's `.brand-logo` image. Two filenames don't match their brand's display name or page slug: **FlyZo is `fzo.png`** (page `flyzo.html`) and **Toy Box is `toyzx.png`** (page `toy-box.html`).

### The file:// constraint — why markup is duplicated but CSS/JS is not

This site is validated by **opening the HTML files directly over `file://`**, not through a server. That rules out any `fetch()`-based shared-include pattern for the nav/footer: under `file://` a page's origin is opaque and `fetch()` of a local file is blocked by CORS. So **the nav and footer markup are duplicated verbatim across every HTML file** — deliberately less DRY, in exchange for actually working when double-clicked. **If you change the nav or footer, change it in all fourteen HTML files** (a scripted find-and-replace across the repo is the sane way to do that, not fourteen manual edits). On subpages the same-page anchors resolve to `index.html#…`; only that href prefix differs from `index.html`'s copy.

`<link rel="stylesheet">` and classic `<script src>` are **not** subject to that restriction and load fine over `file://`, which is why CSS and JS are shared rather than duplicated. Two consequences to preserve:

- Never add `type="module"` to the script tag — ES modules *are* CORS-restricted and would break the page under `file://`. `script.js` must stay a classic script.
- `script.js` runs on both pages, so anything that queries a page-specific element must be null-guarded. The hero-load animation (`.hero`) and the contact form (`#partnerForm`) are already wrapped in `if (…)` checks for exactly this reason; follow that pattern when adding page-specific behaviour. Bare `querySelectorAll(...).forEach(...)` is inherently safe (an empty NodeList just no-ops) and needs no guard.

### CSS design tokens

All colors, shadows, easing curves, and layout constants are defined once as custom properties on `:root` (top of `styles.css`). Always reuse these tokens (`--accent`, `--ink`, `--secondary`, `--ease-snap`, `--maxw`, `--gutter`, etc.) rather than hardcoding new values — the palette is a warm off-white base (`--bg` / `--bg-alt`) with a deep navy ink (`--ink`, sampled from the logo) and a single true-red accent (`--accent`) used sparingly (headline word, buttons, tags, dots, icons — never as a large fill). `--secondary` is a cool slate grey used for body-adjacent UI. The five easing tokens (`--ease-smooth`, `--ease-emphasis`, `--ease-out`, `--ease-snap`, `--ease-panel`) are the intentional motion vocabulary for the whole page.

`section.bg-alt` toggles a section's background to `--bg-alt` for alternating rhythm down the page (via the class: About and Contact; the How We Operate section sets the same `--bg-alt` background in its own `.how` rule) — cards placed on a `bg-alt` section get a visible border, cards on the plain `--bg` sections get a soft shadow instead of a border (the `.flow-step` nodes in How We Operate follow this — border, no shadow).

Two Google Fonts: **Space Grotesk** (display headings, numerals, italics-as-accent, weight 700 for major headings) and **Inter** (body text, UI).

### Page structure

`index.html`'s `<main>` is a sequence of `<section>`s in this order: Hero → Trusted By (logo marquee) → About → Brands (static logo grid, `#brands`) → How We Operate (`#how-we-work` — informational: paragraph + 3-step flow diagram) → Markets (SVG map + list) → Trust stats → Leadership (`#leadership` — a `.leader-teaser` card linking out to `leadership.html`, *not* the founder cards themselves) → Contact → Footer. Nav and footer sit outside `<main>`. Sections are wrapped in `.container` (max-width `--maxw`, centered) except where a section deliberately breaks out full-bleed (see below).

`leadership.html` is a single-section page: the nav, one `#leadership` section carrying both leadership rows, then the footer. Because it has no hero to reserve space under the fixed nav, its section takes the `.subpage-first` class (extra top padding). Any future subpage should do the same.

### About section photo collage

The right-hand column of `.about-grid` is `.about-collage` — a landscape-oriented stack, not a grid: one full-width `.collage-hero` tile (office exterior), then `.collage-row` — three equal `.collage-tile` figures in a row (`gap:12px`), stacking to a single column at `max-width:560px` since three tiles that narrow stop being readable. Landscape ratios throughout are deliberate: an earlier portrait/asymmetric mosaic (3-col × 3-row grid, one tall anchor + stacked side tiles) forced landscape photography into narrow crops, which is why it was replaced.

**The collage's height is structurally tied to the text column's height, not sized independently.** `.about-grid` uses `align-items:stretch` (not `start`), so `.about-collage` — a grid item — is stretched to exactly match `.about-text`'s full rendered height (lede + paragraphs + all pillar cards). Inside that stretched box, `.collage-hero` and `.collage-row` are flex children (`.about-collage` is `display:flex; flex-direction:column`) with `aspect-ratio:16/9` / `aspect-ratio:4/3` supplying their *minimum* size (via `flex-basis:auto` transferred from the aspect-ratio at the column's fixed width) and `flex:2 0 auto` / `flex:1 0 auto` distributing any leftover height between them (roughly preserving the original ~2.3:1 hero:row visual weighting — adjust the `2`/`1` if that balance ever needs to shift). `.collage-row` itself is a flex row (not a grid) so its three tiles — `flex:1 1 0`, ignoring their `aspect-ratio`-implied width in favor of equal thirds — stretch via the default `align-items:stretch` to fill whatever height `.collage-row` was grown to. Net effect: **add a 4th pillar card and the collage visibly grows taller with it, no manual resize.** The tradeoff is that "4:3" and "16:9" are floors, not fixed ratios — tiles run taller than their nominal ratio whenever the text column has more content than the collage's natural size, which is intentional per this design.

**All four photos (`office-photo-optimized.jpg`, `warehouse-optimized.jpg`, `delivery-team-optimized.jpg`, `office-interior-optimized.jpg`) are temporary stand-ins for management review, not final photography.** Each tile carries a `.sample-badge` — a small dark pill, top-right corner, pure CSS overlay — flagging that. It's deliberately just a `<span>` inside the `<figure>`, no JS: **to retire it once real photos are approved, delete the `.sample-badge` span** (and the now-unused CSS rule, if nothing else references it). `.collage-hero img` sets `object-position:center top` to anchor on the office building's roofline peak, since the source photo is a tall portrait shot being cropped into a wide 16:9 tile — same convention as `.hero-photo img`'s crop.

If a tile ever needs to go back to an unphotographed placeholder (e.g. a future fifth tile, or one of these four gets pulled), the brand pages' `.range-media` dashed-border box is the pattern to reuse — that's now the site's only live instance of the convention (the leadership page's `.headshot-pending` went away with the flip cards). It was used here previously as `.tile-pending` before real stand-in photos replaced it, and was removed as dead CSS once no tile referenced it.

### Brands section

`.brand-grid` (`data-stagger`, so cards cascade in via the shared `.stagger-item` reveal system) is a CSS grid of `.brand-card` tiles — **6 columns down to 4 at 900px, 4 at 560px (not 3), 2 at 380px**, 20px gap (a dense directory look, not a sparse showcase). The 560px breakpoint is deliberately the same column count as 900px rather than continuing the step-down — see the confirmed sequence note below for why. The column counts are chosen so all 12 current cards resolve to even rows at every breakpoint (2/3/3/6 rows respectively) — if the card count ever changes, recheck that it still divides evenly at each column count, or a trailing row will look sparse. Each tile is `aspect-ratio:1/1` (a consistent square regardless of logo shape) with a plain bordered/shadowed card style, centered around one `<img>`. `.brand-card` padding steps down at 900px/560px/380px (20px → 16px → 13px → 10px) so wide wordmarks keep real width to work with as the grid narrows — note this padding scale still assumes the old 3-column step at 560px and hasn't been re-tuned for 4 columns there; revisit if cards look cramped at that width. Each `.brand-card` carries a `data-order` attribute and a small JS pass on load copies it into `style.order` — since grid items respect CSS `order`, reordering the directory later is a one-line attribute edit per card, not a markup rebuild.

**Confirmed final sequence** (`data-order` 1–12): D'Toy, The Play Zo, TEQ, Leo Toy, Petal Muse, VOL, D'FUN, Hippo, Toy Box, FunQB, FlyZo, Little Trendz. This was chosen so the first four (D'Toy/The Play Zo/TEQ/Leo Toy) lead as a clean, uninterrupted group at every breakpoint: they fill row 1 exactly at 4 columns (900px and 560px), share row 1 with two more at 6 columns (desktop — not exclusive, but still leading, unsplit), and occupy a dedicated 2-row block at 2 columns (mobile — the only column count where 4 items can't fit one row, but nothing else shares those two rows). The 560px breakpoint was changed from 3→4 columns specifically to fix this: at 3 columns, item 4 (Leo Toy) split off into row 2 next to two unrelated brands instead of leading with items 1–3. **If this sequence changes, re-run this row-math check** — it only holds for this exact order.

Logos target 68px tall but use `.brand-card img{width:100%; height:68px; object-fit:contain}`, not `height:68px; width:auto` — the source PNGs range from near-square (Funqb, Fzo) to very wide (VOL is 2.44:1, Dtoy 2.33:1), and on a *square* card a wide wordmark can hit the card's width limit before it hits 68px tall. `object-fit:contain` scales the whole logo down proportionally in that case (both dimensions together, ratio intact) instead of the width being clipped or squashed against a fixed height — same "don't force a uniform box" intent as the retailer logo marquee's `.logo-item img`, just solved with `contain` instead of `height:Npx;width:auto` because the container is square rather than free-height.

Each card holds a `.brand-pop` speech-bubble callout (brand name in `--accent`, one product-category line below) that reveals on hover/tap. It follows the **same dual-trigger pattern as the leadership rows**: `:hover` shows it on pointer devices, and a `.pop-open` class (toggled by a click listener in the `<script>`) covers touch — but unlike those, opening one callout closes any other, and a click outside `.brand-card` dismisses it (better tooltip UX for 12 tiles). The bubble is `position:absolute`, centered above the card by default, with a two-triangle arrow (`::before` = `--line` border, `::after` = `--surface` fill inset 1px) so the pointer keeps the bubble's hairline border. It stays `pointer-events:none` even when shown — purely informational, never steals hover or blocks a future card link. Top-row cards would open up into the section heading, so a `markBrandTopRow()` JS pass (run on load + rAF-throttled resize) adds `.pop-below` to whichever cards share the minimum `offsetTop` at the current column count, flipping their callout (and arrow) downward. Product categories are only confirmed for FlyZo (`fzo.png`), Leo Toy (`leo-toy.png`), Toy Box (`toyzx.png`), Petal Muse (`petal-muse.png`), TEQ (`teq.png`), Little Trendz (`little-trendz.png`), The Play Zo (`the-play-zo.png`), Hippo (`hippo.png`), and D'Toy (`dtoy.png`); the other three use the bracketed `[PRODUCT TYPE — PENDING]` placeholder per the content-accuracy policy. Note the callout **brand names differ from the img `alt`** where a final name was given — `alt="Fzo"` shows "FlyZo", `alt="Toyzx"` shows "Toy Box", `alt="Vol"` shows "VOL"; the `.bp-name` text is the authoritative display name. Like every other animated element, `.brand-pop` has a `prefers-reduced-motion` override (opacity-only fade, no scale/slide).

**Every tile is a link.** All twelve are `<a href="<slug>.html" class="brand-card stagger-item" data-order="N" aria-label="<Name> — view brand page">`, not `<article>`. Both CSS and JS hook off the `.brand-card` *class*, never the element name, so the hover callout, `.pop-open` toggling, `markBrandTopRow()`, and the stagger reveal are unaffected by the element choice. `.brand-card`'s long-standing `cursor:pointer` is now accurate for every tile. One touch-device consequence: a tap navigates rather than opening the callout, so on touch the callout is effectively hover-only — that's normal link behaviour, not a regression.

### Brand detail pages

There are twelve of these, one per Brands-grid tile. **Two page states share one skeleton** — `flyzo.html` is the reference copy for a launched brand, `vol.html` for a pending one:

- **Launched** (nine brands): `.brand-hero.subpage-first` (breadcrumb → `.brand-intro`) → `.brand-strip` feature band (**omitted entirely** on brands with no confirmed features) → a `.bg-alt.brand-range` range section of exactly three `.range-card`s → `.brand-cta` closing block.
- **Coming soon** (`vol.html`; the template for the remaining pending pages): identical hero and closing CTA, but the range section is replaced wholesale by `.bg-alt.brand-soon` — see *"Coming soon" state* below.

Nothing follows the CTA but the footer in either state.

**Content status varies; structure does not.** Nine brands now have confirmed tagline + body copy — FlyZo, Leo Toy, Toy Box, Petal Muse, TEQ, Little Trendz, The Play Zo, Hippo, and D'Toy — but they diverge from there, so don't assume one implies another:
  - **Feature strip**: only FlyZo, Leo Toy, and Toy Box have one (real specs were supplied for them). Petal Muse, TEQ, Little Trendz, The Play Zo, Hippo, and D'Toy have none — no strip copy was ever given for them, so `.brand-strip` is omitted entirely on those six, same as on the fully-pending brands.
  - **Range slots filled**: FlyZo, TEQ, and The Play Zo each have two of three real products; Leo Toy and Toy Box have one of three; **Hippo has only one of three** (X-Force on `r-lg`; `r-a` and `r-b` both stay on the standard pending "Coming Soon" card — the sparsest confirmed page); **Petal Muse, Little Trendz, and D'Toy are the only three brands with all three range slots filled** (zero pending cards on any of the three).
  - **Per-product spec copy**: Petal Muse's three cards all carry a full-sentence `.range-desc`.   Three brands have no confirmed category, description, or products — **VOL, D'FUN, and FunQB** — and **all three are now on the coming-soon treatment below**; none of them carries a bracketed `[… — PENDING]` placeholder anymore. Their `<head>` descriptions deliberately avoid inventing a category, asserting only confirmed facts ("a consumer brand owned and built by DAT International, … Ajman, UAE") plus the coming-soon status. Per the content-accuracy policy, don't fill any of these in without supplied copy — and when copy *does* arrive, converting a page back means reversing the three swaps below, not patching the soon panel.

#### "Coming soon" state (`vol.html` is the locked template; also on `dfun.html`, `funqb.html`)

Three empty dashed `[PHOTO PENDING]` cards read as a *broken* page; one deliberate panel reads as a brand that simply hasn't launched. So pending brands drop the range section entirely instead of dressing up its placeholders. The CSS lives under *"Coming soon" state* in `styles.css`, immediately after `.brand-cta`, and is **fully brand-agnostic** — converting another pending page is three markup swaps and **no new CSS**:

1. `.brand-tagline` → `.brand-status` — a pill ("● Coming Soon") taking the category eyebrow's slot via the same `order:-1` hoist, so the intro keeps its shape while asserting nothing about a category that isn't known. The accent dot pulses via `status-pulse`; under `prefers-reduced-motion` the ring is dropped and the solid dot carries the signal.
2. `.brand-desc` → **deleted outright** — no invented body copy. The hero is deliberately just name + pill; the panel below carries the message.
3. The whole `.brand-range` `<section>` → the `.brand-soon` `<section>`.

The panel (`.soon-panel`) is a bordered surface card carrying: a masked dot-matrix texture on `::before` (`radial-gradient` dots, `mask-image` fading them out under the copy so text sits on clean surface — where `mask-image` is unsupported the grid just covers evenly, still deliberate, so no `@supports` fallback is needed); `.soon-monogram`, the brand's initial set huge in Space Grotesk at `opacity:0.035` — **purely typographic, so a brand with zero photography still gets a graphic**; then `.soon-eyebrow` / `.soon-title` / `.soon-note` / `.soon-actions` / `.soon-meta`. **The only per-page value in the entire block is the single letter inside `.soon-monogram`.**

The panel's one CTA points back to the Brands grid; the contact ask is left to the `.brand-cta` ink panel below, so the two don't duplicate each other. `.soon-meta` repeats only already-confirmed facts (owned & built by DAT International · Ajman, UAE) to signal an owned, live page rather than an abandoned one. No JS beyond the shared `.reveal` observer — the panel takes a single `.reveal`, its children none.

All three pages' `<main>` blocks are **verified byte-identical once the brand name, monogram letter, and logo path are normalized out** (comments differ only in wording — vol.html names itself the source, the other two name it as their origin). If you edit one, propagate to the other two and re-run that check; the shared nav/footer across all twelve brand pages is likewise still a single distinct variant each.

These twelve pages were generated from a template rather than hand-written, so the nav, footer, `<head>` chrome, and section scaffolding are byte-identical across all of them (verified by string comparison) — see the file:// constraint note above for what that means when editing shared chrome.

The CSS lives under *Brand detail pages* in `styles.css` and is deliberately **brand-agnostic** — `.brand-hero`, `.brand-hero-deco`, `.breadcrumb`, `.brand-intro`, `.brand-intro-text`, `.brand-name`, `.brand-tagline`, `.brand-desc`, `.brand-logo`, `.brand-strip`, `.brand-range`, `.range-grid`, `.range-card`, `.range-media`, `.brand-cta`, `.brand-cta-deco`, plus the coming-soon set (`.brand-status`, `.brand-soon`, `.soon-panel`, `.soon-monogram`, `.soon-inner`, `.soon-eyebrow`, `.soon-title`, `.soon-note`, `.soon-actions`, `.soon-meta`). Build the next brand page on these same classes; don't fork per-brand variants. Specifics worth knowing:

- **Decorative shapes.** `.brand-hero-deco` (`opacity:0.045`, `rotate(24deg)`) bleeds off the **top-right** — deliberately faint and pushed well off-canvas (`top:-190px; right:-170px`) because the logo sits flush right in that corner; keep it as background texture, don't let it compete. It's an empty `<span aria-hidden="true">` with `pointer-events:none` at `z-index:0`, clipped by the section's `overflow:hidden`, below `.container` (`z-index:2`). Keep that contract for any further shapes. `.brand-cta-deco` still exists in all twelve pages' markup but is now `display:none` — the closing CTA's accent comes from the ink panel's internal glow instead (below).
- **The closing CTA is an ink panel**, not a plain centered block: `.brand-cta .container` gets an ink background, `--radius-lg` corners, and a corner radial-red glow via `::before` — the exact device index's `.trust::before` uses, so brand pages close on the same "dark chapter" note the main page already has rather than introducing a separate dark theme. The panel width is `calc(100% - 2*var(--gutter))` capped at `calc(var(--maxw) - 2*var(--gutter))` so it floats inside the gutter on every viewport instead of bleeding to the screen edge.
- **Vertical rhythm is deliberately tightened here.** `.brand-hero` overrides the default section padding with `padding-bottom:clamp(30px,4vw,44px)` and `.brand-range` with `padding-top:clamp(34px,4.5vw,52px)`, so intro → strip → range reads as one flow instead of three separately-padded blocks. Don't restore the stock `section` padding between them.
- **`.brand-strip`** is a plain `<div>`, *not* a `<section>` — deliberately, so it doesn't inherit the tall default `section` padding. Bordered band, centered uppercase items separated by `.strip-dot` spans (accent-coloured, `aria-hidden`).
- **`.brand-intro` is a two-column hero**: a `.brand-intro-text` block on the left and the `.brand-logo` image flush right. **Visual order within the text block is tagline → name → body, but DOM order keeps the `<h1>` first** — `.brand-intro-text` is a flex column and `.brand-tagline{order:-1}` hoists the tagline above the name as the page's eyebrow (same accent small-caps + 24px-dash convention as `.section-head .eyebrow`; it gains a symmetric `::after` dash when centered on mobile). `.brand-name` runs `clamp(42px,6vw,64px)`; `.brand-desc` is 17px at `max-width:54ch`. At ≤760px `.brand-intro` becomes `flex-direction:column-reverse` + centered, which puts the logo *above* the text visually while keeping DOM order text-first; the breadcrumb centers to match.
- **`.brand-logo` is a bare image — no container chrome.** No border, `border-radius`, background fill, shadow, or padding (an earlier circular-badge treatment was removed). The wrapping `<div>` exists *only* to carry the `.reveal` hook and must stay `padding:0; margin:0` so the logo sits flush against the right edge of the content column. Sizing is **height-pinned with `width:auto`** (110px → 92px under 1000px → 80px under 760px) so every brand keeps its own aspect ratio; sources run 0.89:1 (FunQB) to 3.68:1 (TEQ). The 1000px step exists because TEQ renders ~404px wide at 110px tall and would starve the text column before the stacking breakpoint — check the widest logo before changing these heights.
- The `<h1>` is the brand **name as text**, not the logo image (two earlier iterations — a `.brand-wordmark` styled-text treatment, then an image-in-`h1` — were both replaced and their CSS removed as dead). The logo `<img>` carries `alt="<Name> logo"`.
- **Don't reintroduce a `.brand-intro p` rule.** An element selector there is specificity `0,1,1` and silently beats `.brand-tagline`'s `0,1,0`, overriding its accent colour with `--ink-2` — that was a real bug. Body copy is scoped to the `.brand-desc` class for exactly this reason.
- **`.range-grid`** is intentionally asymmetric (`1.4fr 1fr`, with `.r-lg` spanning both rows beside stacked `.r-a`/`.r-b`) — *not* a uniform e-commerce grid. Collapses to one column at 760px, where the explicit `grid-column`/`grid-row` assignments are reset to `auto`.
- **`.range-media`** is a static "Coming Soon" card by default — the pending-slot treatment for individual unfilled products on an otherwise-launched brand page (distinct from the full-page `.brand-soon` state above, which replaces this section entirely). **This replaced an earlier dashed-hatch-and-shimmer "pending, not broken" design** (a `repeating-linear-gradient` hatch + an animated `rm-shimmer` sweep on `::after`) — that CSS, and FlyZo's theme-flight-exclusive radar-scope variant of it (HUD grid background + conic `radar-sweep`), are both gone; don't reintroduce either. The current version is deliberately calm and un-animated: solid `--bg-alt` fill, a thin `1px solid var(--line)` border for definition, an `.rm-icon` (a clock glyph, `color:var(--ink)`) above `.rm-title` ("Coming Soon", Space Grotesk/`--ink`) and `.rm-sub` ("New arrival on the way", Inter/`--secondary`). **No `<h3 class="range-name">` sibling on a pending card** — the old `[PRODUCT NAME — PENDING]` label is removed outright, not just re-styled; the card is self-contained. Because it has no animation, it needs no `prefers-reduced-motion` override at all — a first for this component. Distinct from a filled slot (`.has-photo`, which drops the border) so it's never mistaken for a real product. Currently appears on FlyZo (`r-b`), TEQ (`r-b`), The Play Zo (`r-b`), Leo Toy (`r-a`/`r-b`), Toy Box (`r-a`/`r-b`), and Hippo (`r-a`/`r-b`) — nine pending slots across six pages, all sharing this exact markup (icon SVG, `.rm-title`, `.rm-sub`) verbatim.
- **`.range-media.has-photo`** is the real-photo variant, replacing the pending treatment entirely — no hatch, no shimmer (`::after{content:none}`), no dashed border, no `.rm-inner`/`.rm-icon`/label markup, just a bare `<img>`. ### Scroll-triggered reveal system

There are several distinct but related `IntersectionObserver`-driven animation patterns in `script.js` — understanding which one applies where matters before adding new animated content:

- **`.reveal`** — single-element fade/slide-up, triggered once by the shared `revealObserver`. Optional `data-delay="1"`–`"4"` attribute adds a staggered CSS `transition-delay` (80ms increments) for elements revealing together.
- **`.stagger-item`** inside a `[data-stagger]` container — for grids/lists (category cards, market rows) where children should cascade in one-by-one rather than all at once. The `staggerObserver` sets each child's `transition-delay` in JS (75ms increments) when the container enters view, rather than using fixed `data-delay` values.
- **`[data-leader]`** — separate `leaderObserver` for the Leadership rows (kept distinct from the generic stagger system). Note this only drives the outer `.leader-row` reveal (fade/slide-up on scroll-in); the slide-apart interaction inside is a completely separate mechanism (see below). The reveal's `translateY` deliberately lives on `.leader-row` while the interaction's `translateX` lives on the nested `.leader-portrait` — keeping them on different elements is what stops the two transforms from overwriting each other.
- **`[data-count]`** — number elements animated by `countObserver` via `requestAnimationFrame` easing (used for stat blocks).
- **Hero content** does not use scroll-triggered reveal at all — it uses a *load*-triggered system instead: `.hero.loaded` is toggled on `window.load` (with a `setTimeout` fallback), and hero children stagger in via a `--i` CSS custom property multiplied into `transition-delay`.

Any new animated element must also get a corresponding override in the `prefers-reduced-motion` media query at the bottom of `styles.css` — this list has been extended several times as new animated elements were added (`.stagger-item`, `.marquee-track`, `.hero-bg`, `.hero-icon`, `.leader-row`/`.leader-portrait`/`.leader-panel`, `.brand-pop`) and is easy to forget.

Hero parallax (`.hero-bg` — the icon layer only, drifts at 0.35× scroll speed) and the magnetic-pull effect on `.btn-primary` buttons are both plain JS (rAF-throttled scroll listener / `mousemove` listener respectively), and both are gated behind a single `reduceMotion = matchMedia('(prefers-reduced-motion: reduce)')` check at the top of the script.

### Leadership slide-apart rows (on `leadership.html`)

These live on `leadership.html`, not `index.html` — the main page only carries the `.leader-teaser` card that links to them. **This replaced an earlier 3D flip-card treatment** (`.founder-card` / `.founder-inner` / `.founder-face` / `.founder-front` / `.founder-back` / `.front-bar` / `.f-tag`, plus a `.flipped` class); all of that CSS, markup, and JS is gone — don't reintroduce those class names.

`.leaders-grid` is now a vertical flex column of two `.leader-row` articles — **Mashood on top, Mahroof below, stacked, never side by side.** Each row wraps a `.leader-stage` holding two siblings: `.leader-portrait` (a `.lp-role` label sitting 9px above the `.founder-photo` image, so the role reads as attached to the portrait rather than floating) and `.leader-panel` (name, bio, italic quote — the content that used to be on the flip-card back). The role label moved *out* of the panel and above the portrait, so "Chairman"/"Vice Chairman" appears exactly once per row.

**The interaction is a split, not a reveal-beside.** At rest the portrait is centred in the stage and the panel sits invisibly at that *same* centre point; on activation the portrait slides left and the panel simultaneously fades and slides right, so the pair reads as one object coming apart. Timing is 450ms `--ease-panel` (`cubic-bezier(.4,0,.2,1)`, a token added for this) for both slides, with a faster 350ms fade on the panel's opacity. The panel is `z-index:0` behind the portrait's `z-index:1`, which is what makes it look like it emerges from underneath.

The travel distances are **derived, not hand-tuned**: the stage is set to exactly the open composition's width (`--portrait-w` + `--pair-gap` + `--panel-w`), so "centred at rest" and "centred when open" are the same box, and each half's shift is just the distance from that shared centre to its own slot — `--portrait-shift:calc((var(--panel-w) + var(--pair-gap)) / 2)` and `--panel-shift:calc((var(--portrait-w) + var(--pair-gap)) / 2)`. Change any of the three widths and the two halves still meet with exactly `--pair-gap` between them; **don't replace these with literal pixel values.**

**The breakpoint is load-bearing, not cosmetic, and it moves whenever the sizing does.** Portrait is currently `--portrait-w:380px` at aspect-ratio `260/320` (~380×468px rendered — bumped up three times from an original 300×386px: to 340×418px, then 350×431px, then +30px more), with `--panel-w:581px` and `--pair-gap:50px` scaled by the same ratio each time so the panel keeps the same relative spacing off the photo. That's a 1011px open composition, and with the gutter capped at `clamp(20px,5vw,48px)`'s 48px ceiling, the container only clears that at viewport ≈1107px — so the split is gated to `@media (min-width:1120px)` (a small buffer above the exact floor), paired with `@media (max-width:1119px)` for the narrow fallback. The two blocks are deliberately mutually exclusive: the wide block owns all the absolute positioning and slide transforms, the narrow block drops the panel into normal flow *below* the portrait (its own `.leader-portrait{width:min(100%,420px)}` cap), hidden with `display:none` and shown via a `leader-panel-in` keyframe. Neither has to undo the other's positioning. **If you change `--portrait-w`/`--panel-w`/`--pair-gap` again, recompute this breakpoint** — container = viewport − 2×gutter must be ≥ their sum — rather than leaving it at a stale value. **Note the split now only activates above 1120px** — that's past many laptop viewports (1024px, 1112px iPad-Pro-landscape, etc.), which now get the stacked-panel-below fallback instead of the slide-apart; worth knowing before increasing these sizes further, since each bump narrows the audience that ever sees the signature interaction.

Dual trigger, same idea as the brand callouts: `:hover` on `.leader-stage` for pointer devices (the stage spans the full open composition, so the panel stays open as the cursor moves toward it), plus a `.leader-open` class on `.leader-row` toggled in `script.js`. That click listener is bound to **`.leader-portrait`, not the row** — binding it to the row meant tapping the open panel collapsed the thing you were reading. The portrait also carries `tabindex="0"`, `role="button"`, and `aria-expanded`/`aria-controls`, with an Enter/Space keydown handler, because the bio and quote are otherwise reachable by hover alone. On wide viewports the panel is hidden with `opacity:0` rather than `display:none`/`visibility:hidden` specifically so that content stays in the accessibility tree while closed.

Under `prefers-reduced-motion` the panel still appears and disappears — it just stops travelling to get there. The end-state transforms are left intact on purpose; zeroing them would drop the panel back on top of the portrait it's meant to sit beside.

### Infinite marquee pattern (used twice: hero ticker + logo strip)

Both `.hero-strip-track` and `.marquee-track` are seamless CSS-only infinite scrollers (duplicated content + `translateX` keyframe + `animation-play-state: paused` on hover). The non-obvious constraint: **item spacing must come from per-item `margin-right`, not the flex `gap` property.** `gap` on a row of N items produces only N−1 gaps, which breaks the exact fractional math the loop depends on (e.g. `-25%` needing to land precisely at the start of the 2nd of 4 duplicated sets). Per-item margin gives every item an equal `width + margin` contribution, so the row splits into exact equal fractions and the `translateX` endpoint (`-50%` for a 2× duplicate, `-25%` for a 4×) always lands exactly on a repeat boundary with no visible seam jump.

### Full-bleed breakout

Two different techniques are used for elements that need to span the viewport edge-to-edge, ignoring `.container`'s max-width — pick based on context:
- **`position: absolute; left/right: 0`** anchored to a `position: relative` ancestor (used by `.hero-strip`, which overlays the bottom of `.hero` without needing its own reserved layout height).
- **`width: 100vw; margin-left/right: calc(50% - 50vw)`** (used by `.marquee`) when the element needs to stay in normal document flow (has real height) and there's no suitable `position: relative` ancestor to anchor to.
